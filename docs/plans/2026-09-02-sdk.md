# Grid SDK: a Rust client crate and a Python client over wire v1

Status: **planned**, 2026-09-02. Written in the shape of
`docs/plans/2026-09-01-agent-loop.md`: every step
one commit with the gates green (`just check`, read by exit code), its
conservatism test seen red first with the mutation named in the commit
message, and its deviations listed at the top of the document when it
lands. **No new packages**: the Rust client is `std::os::unix::net` plus
`grid-wire`, `serde`, `serde_json`; the Python client is `json` + `socket`
and nothing else, mechanically.

## Context

"SDK" is defined nowhere in the repo. Settled with the user on 2026-09-02:

- **In scope, in order:** (a1) a Rust client crate `grid-client` speaking
  wire v1 to `grid serve`; (a2) a zero-dependency Python client.
- **Out of scope, recorded:** a TypeScript client (no TS frontend yet;
  it would bring a `package-lock` the dependency law does not describe); an
  MCP toolkit (declined); an embeddable engine crate (the composition root
  lives in the bin-only `grid` crate — `rpc.rs` 2205 lines, `main.rs` 2459,
  both on the hygiene debt list — so extracting it is a refactor with its
  own plan).

Why a client at all: the only way to speak to the daemon today is to
hand-roll what `crates/grid/tests/conformance.rs` does — connect, write a
line, read a line, `serde_json::from_str`. Every consumer would re-derive
the framing, the id rule, the eight codes and the version rule.

Findings from the reading, recorded rather than fixed here. Each becomes a
`docs/TODOS.md` row in step 0:

- **Two contract methods are not served.** `grid.anchor.carry` and
  `grid.plan.estimate` are among the contract's 23 methods and absent from
  `serve.rs`'s 21 dispatch arms, so they answer `-32601`. C10 ("every wire
  method the daemon claims is answered over the real socket") does not hold
  for them, and `conformance.rs` calls neither.
- **`grid serve` unlinks the socket path before binding.** A second daemon
  started on a live socket steals it: the first keeps serving an unlinked
  inode, and whichever exits first deletes the survivor's file. This is why
  the client adopts and never spawns (answer 4).
- **The daemon never emits error `data`,** though the contract declares a
  shape per code. `serve.rs` writes `code` and `message` only.
- **The contract's major-refusal sentence has no mechanism.** "The daemon
  refuses clients that pin an incompatible major" — `VersionParams` is
  empty, so a client cannot pin anything.
- **`WIRE_VERSION` is a hand-written constant** in `main.rs` beside the
  contract's `info.version`; the drift gate cannot see it. Step 1 fixes it.
- `x-porcelain.doc` names `packages/grid/docs/PORCELAIN.md`, a path that
  does not exist in this repo. One-line contract fix in step 1.

## The ten answers

**1. Generation** (CLAUDE.md: `grid-wire` is generated, never hand-edited;
C47). Generated from the contract by `scripts/gen-wire.py`, in one run:

| file | added content |
|---|---|
| `crates/wire/src/lib.rs` | `pub const WIRE_VERSION: &str` from `info.version` |
| `crates/wire/src/methods.rs` | `pub trait Method`, one `impl` per method, `pub const METHODS: [&str; N]` |
| `clients/python/grid_client/schemas.py` | one `TypedDict`/`Literal`/`NewType` per schema |
| `clients/python/grid_client/methods.py` | `WIRE_VERSION`, `METHODS`, `WIRE_ERRORS`, one typed method per wire method |

The Rust client carries **no generated file**: its typed surface is one
generic `call<M: Method>`, and the table lives in `grid-wire`, which the
drift gate already covers. Hand-written-and-drift-checked was rejected on
yi's own incident — two spellings of 83 schemas is what
`check_schemas_lock.py` existed to catch.

`errors.rs` **stays hand-written**, against my first draft. C47 already
records that it is outside the generator's reach; generating it would buy
one enum that has changed once, and cost an emitter plus a claim edit. It
gains five lines of `from_code(i32) -> Option<Self>` by hand, and the drift
it could suffer — a ninth code in the contract — is caught by a test rather
than an emitter: `crates/wire/tests/conformance.rs` reads
`components.errors` and asserts every code round-trips through `from_code`
with the contract's own message. Cheaper than a generator and it fails for
the right reason.

`check_wire_drift.py` must cover every path the generator writes or a
contract edit ships without the SDKs. `OUT` becomes a list of generated
paths across both trees, each copied into the scratch tree; `rustfmt`
normalizes the `.rs` only (there is no Python formatter in the TCB, so
`.py` is compared as emitted). `--selfcheck` is strengthened: the
renamed-method perturbation must produce drift in **every** file that
spells method names, so a new emitter that ignores the contract cannot
pass blind.

**2. Dependency law** (no new runtime crate dependency; every `Cargo.lock`
line justified; `deny.toml` bans).

- Rust: `grid-client` → `grid-wire`, `serde`, `serde_json`, all in the TCB
  since wave 1. `Cargo.lock` gains a workspace member and no package.
  `deny.toml` needs no edit; its `tokio`/`reqwest` bans are what keep the
  client synchronous and socket-only. ASSURANCE.md gains one paragraph
  under *Dependency justification*: "Wave 12 (`client`): no new packages."
- Python: **ships dependency-free**, and the law extends to say so
  mechanically. `clients/python/pyproject.toml` declares
  `dependencies = []` and `requires-python = ">=3.11"` (the floor the
  guardrails already set through `tomllib`). There is no lockfile because
  there is nothing to lock. `check_manifests.py` gains one block: fail if
  `project.dependencies` or any `optional-dependencies` is non-empty, fail
  if `project.name != "grid-client"`, fail if any of `uv.lock`,
  `poetry.lock`, `requirements*.txt`, `Pipfile*` exists under `clients/`.
  ASSURANCE says: the Python client's TCB is CPython's standard library,
  and the gate refuses the first line that changes that.
- Dev tooling: `mypy` joins the optional-tool list in
  `scripts/check-guardrails.sh`, CI installs it beside `codespell`. A
  binary on `PATH`, not a dependency — the only kind of tool this repo adds.

**3. Naming and boundaries** (folder `x/` is crate `grid-x`;
`boundaries.toml` is an allowlist).

- `crates/client/` → `grid-client`; the naming law holds unchanged.
  `boundaries.toml` gains `"grid-client" = ["grid-wire"]`, so the schema
  wall stays the only shared surface and the client never sees the engine.
  `grid` gains a **dev**-dependency on `grid-client` for the socket tests;
  `check_boundaries.py` reads `dependencies` and `build-dependencies` only,
  so a comment in `boundaries.toml` records that edge. No cycle is possible
  — `grid` has no lib target.
- Python lives **outside** `crates/`, at `clients/python/`, so
  `check_manifests.py`'s glob over `crates/*/Cargo.toml` stays true by
  construction: `crates/` holds Rust and nothing else. The naming law
  extends by analogy and is enforced by the block above: the package under
  `clients/<lang>/` is `grid-client` in that language's spelling
  (`grid-client` distribution, `grid_client` import). No
  `clients/typescript/` directory is created.

**4. Transport and lifecycle** (`x-transport`; `serve.rs` serves
connections serially, answers a notification with silence, and reports a
parse error against id `null`).

- Socket path: explicit argument > `GRID_SOCKET` > `<root>/.grid/grid.sock`
  with root defaulting to the process cwd. The daemon resolves its own
  default against *its* cwd, which the client cannot know; the doc says so.
- **Adopt, never spawn.** `Client::connect(path)` requires a running
  daemon. A refused connection is `Error::NoDaemon(path)` carrying the hint
  `run grid serve in <root>` — the refusal-a-survey-would-fix shape
  PORCELAIN prescribes. A `spawn` constructor was in the first draft and is
  cut: `grid serve` unlinks its socket path before binding, so spawning
  against a live socket silently steals it, and the tests that need a
  daemon already have the harness in `conformance.rs`. Lifecycle is the
  caller's; the SDK owns no process.
- Handshake: `connect` issues `grid.version` first (answer 6).
- One call is one line written and flushed, one line read. Ids come from a
  `RequestId(u64)` newtype and a per-connection counter with `checked_add`;
  exhaustion is a typed error. The client sends no notification (a write
  with no ack) and no batch array (the daemon answers an array `-32600`).
- **Pipelining is not exposed.** The transport allows it and the daemon
  answers in order; a `pipeline()` API was in the first draft and is cut as
  speculative — it buys round trips on a local socket against a serial
  daemon, and drags an out-of-order correlation path nothing exercises.
  What is kept is the property that makes pipelining safe later: **every
  response is matched to its request by id**, and one that does not match
  is a fault, never attributed to the outstanding call.
- Faults, each poisoning the connection (later calls return
  `Error::Closed`; the caller opens a new client, and `serve_conn` holds no
  per-connection state so a fresh one is equivalent):
  - EOF at a line boundary → `Error::Disconnected` (daemon exited, or was
    started `--once`).
  - EOF inside a line → `Error::Protocol(Truncated)`. A partial line is
    never parsed.
  - An id that is not the outstanding one, or `null` (the daemon could not
    parse what the client wrote) → `Error::Protocol(UnexpectedId)`.
  - Both `result` and `error`, or neither; `jsonrpc` ≠ `"2.0"`; not an
    object; not UTF-8 → `Error::Protocol(..)` naming which.
  - `set_read_timeout(Option<Duration>)` is a one-line delegate to the
    std socket, off by default because `grid.check` and a cold
    `survey.run` are seconds; a timeout surfaces as `Error::Io` with the
    kind std reports.
- **No automatic reconnect and no retry.** Three methods write
  (`survey.run`, `edit.apply`, `cache.record`); a silent re-issue is a
  second write.
- `Client` takes `&mut self` and is `!Sync`: one connection each.
  Concurrency is more clients, and buys nothing while the daemon is
  serial. The doc says that rather than hiding it behind a pool.

**5. Errors and non-errors** (eight codes; fuel exhaustion is a result;
wire-facing enums stay decodable).

- Rust: `#[non_exhaustive] enum Error { Io, Protocol(Protocol),
  Rpc(RpcError), Incompatible { daemon, client }, Decode { method,
  daemon_wire, source }, NoDaemon(PathBuf), Disconnected, Closed,
  IdsExhausted, Encode }`. `RpcError { code: i32, wire: Option<WireError>,
  message: String, data: Option<Value> }` — `wire` is
  `WireError::from_code(code)`, so a ninth code, or any of `-32601`,
  `-32602`, `-32603`, `-32700`, arrives with `wire: None` and the integer
  intact. Nothing turns an integer into a `WireError` by a match with a
  panic arm. `data` decodes as `Option<Value>`: the daemon does not send it
  today and the contract says it may.
- Aground stays `Ok(WalkResult { status: Aground, frontier, stats
  .complete_within })`. The client converts nothing and adds no `resume`
  helper — the contract's own rule is "issue a new walk from the frontier",
  and a `no_run` doc example shows exactly that.
- Python: `GridError(Exception)` with `.code: int`, `.message`, `.data`,
  and `.wire: str | None` looked up in the generated `WIRE_ERRORS` dict —
  a lookup, never a constructor that raises on an unknown code. Transport
  faults are `GridProtocolError` / `GridConnectionError`, disjoint from
  `GridError`, so `except GridError` cannot swallow a desynced socket. A
  walk that ran aground is a dict whose `status` is typed
  `Literal["complete", "aground"]`.

**6. Versioning** (contract convention 5; additive-only within an epoch).

- The SDK's own version is the crate's and the package's (`0.1.0`, as every
  workspace crate — `check_manifests.py` requires one). Its compatibility
  pin is the generated `WIRE_VERSION`: one constant, three consumers
  (`main.rs`, both clients), so they cannot disagree about what "1.1.0" is.
- Handshake: `connect` calls `grid.version`, compares **majors only** — the
  digits before the first `.`, no semver type and no dependency — and
  refuses a different major with `Error::Incompatible { daemon, client }`
  before any other call. A `wire` string with no leading integer is
  `Protocol`. The refusal is client-side because the daemon has nothing to
  refuse on; that gap is a TODO row, not built here.
- Client 1.1 against daemon 1.2: connect succeeds. Rust results decode
  under `deny_unknown_fields`, so a result whose shape grew fails to
  decode, and that failure is `Error::Decode { method, daemon_wire, .. }`
  naming both versions rather than a bare serde message; `call_raw`
  (returning `Value`) is the forward-compatible path, and every result that
  did not grow keeps working. Python gets the extra keys as dict entries.
  Relaxing `deny_unknown_fields` was rejected: the engine deserializes
  several wire types from disk (`Plan`, `Trace`, `CompileRecord`), and a
  tolerant reader there is the silent drop the flag exists to forbid.
- Client 1.2 against daemon 1.1: connect succeeds; a 1.2-only method is the
  daemon's `-32601`, a 1.2-only param is its own `deny_unknown_fields`
  `-32602`. Both arrive as `Rpc` with the code and the method named.

**7. Determinism** (contract convention 4; C2's property test).

The SDK **does not cache**. The key would be `(snapshot_id, method,
canonical params)` with `stats` stripped, valid only when the caller
pinned `snapshot` and left `fuel.max_ms` unset — every one of those is the
caller's decision, so the key belongs to the caller. The plan states it so
a caller can build one; the client exposes nothing that would make two
identical calls differ (no id in results, no reordering). Evidence: the
socket test issues the same pinned `grid.query.walk` twice through the
client and compares with `stats` stripped, which is C2's comparison
surface reached through the client instead of the engine.

**8. Testing doctrine** (one externally observable contract per test; red
before green; a round-trip is not correctness; climb har-verify and stop).

Rust:

- **Differential against the CLI's `--json`** (`crates/grid/tests/client.rs`):
  for `version`, `resolve`, `diff`→`grid.delta`, `drift` and `scope`, the
  CLI's `--json` stdout parsed as a `Value` equals the client's typed
  result re-serialized. The CLI runs every verb in-process through the same
  `rpc::*` functions the daemon dispatches to and opens no socket
  (`main.rs` contains no `UnixStream`), so the comparison isolates exactly
  what the SDK adds: `serve.rs` framing plus the client's encode, match,
  decode.
- **Every method the contract names is dispatched:** loop `METHODS`, call
  each with the contract's own `examples` params (all 23 methods carry at
  least one, so no second table is hand-written), assert no answer is
  `-32601`. Two are today, so the test carries `UNSERVED =
  ["grid.anchor.carry", "grid.plan.estimate"]` — a ratchet that starts
  where it lands and only shrinks. Removing an entry while the daemon still
  answers `-32601` is the red that proves the loop.
- **Fault table**, one test per row of answer 4 against a fake daemon
  (`UnixListener` on a thread, scripted replies), each seen red by removing
  the guard it names: a truncated line parsed as JSON, a foreign id matched
  to the outstanding call, a body carrying both `result` and `error`.
- **Handshake:** a fake daemon answering `wire: "2.0.0"` yields
  `Incompatible` before any second write (the listener asserts it received
  exactly one line); `wire: "1.2.0"` with an extra key in the result yields
  `Decode` naming both versions.
- **The round-trip that is NOT accepted as correctness evidence:**
  `Params → JSON → Params` equality. `crates/wire/tests/conformance.rs`
  already does it for every contract example; the client repeats none of
  it, because it proves serde is symmetric and says nothing about what the
  daemon accepts.
- **Fuzz rung** (har-verify rung 4 — the client decodes bytes it did not
  write): `fuzz/fuzz_targets/client_response.rs` over
  `grid_client::decode_line(&[u8])`, the one function turning socket bytes
  into a typed response. Any panic is a finding; `fuzz-build` in CI
  compiles it beside the three existing targets. Rung 8 is not climbed: the
  decoder is `serde_json` plus a match on a `forbid(unsafe_code)` crate
  under the panic-deny lint set, and kani would prove what clippy already
  refuses to compile.
- Doc tests (rung 2) on every public item, `no_run` where a daemon is
  needed. `cargo doc --document-private-items` is in the guardrails, so a
  bare-backtick item name fails the build.

Python (`unittest`, stdlib):

- **Differential against `--json`:** the same five verbs, the CLI's stdout
  against `client.<method>(...)`, exact equality.
- **Fault table and handshake** against a `socketserver.UnixStreamServer`
  on a thread — the same rows as Rust, so the two clients cannot disagree
  about what a fault means.
- **The fuzz rung's stand-in is corpus replay, not a second fuzzer:** every
  artifact the Rust fuzzer minimized under `fuzz/corpus/client_response/`
  is fed to `grid_client._decode_line`, which must raise
  `GridProtocolError` or return — a differential across the two decoders
  over inputs found by the rung that exists. A seeded byte-mutation loop
  was in the first draft and is cut: writing a fuzzer to avoid installing
  one is the bloat the ladder forbids.

## Design

### Generator (`scripts/gen-wire.py`)

- `lib.rs` gains `pub const WIRE_VERSION: &str = "<info.version>";`.
- `methods.rs` gains the trait, one impl per method, and `METHODS` in
  contract order:
  ```rust
  pub trait Method: serde::Serialize {
      const NAME: &'static str;
      type Result: serde::de::DeserializeOwned;
  }
  impl Method for ResolveParams { const NAME: &'static str = "grid.resolve"; type Result = ResolveResult; }
  ```
  One wrinkle the generator already knows: `grid.bisect`'s result *is* the
  schema `BisectResult`, which `methods.rs` deliberately does not import
  (the existing self-alias skip), so that impl spells `super::BisectResult`.
- Python emitter: the same recursion as `rust_type`, re-parameterized as
  `py_type` — `object` → `TypedDict` with `NotRequired[...]` for optional
  fields, `string+enum` → `Literal[...]`, transparent string → `NewType`,
  `array` → `list[...]`, `oneOf` → a `Union` of per-variant TypedDicts,
  anonymous nested objects named exactly as the Rust emitter names them
  (`parent + Camel(prop)`), so one schema has one name in both languages.
  Descriptions become docstrings. `methods.py` carries `WIRE_VERSION`,
  `METHODS`, `WIRE_ERRORS` (code → name, from `components.errors`) and one
  method per wire method on a `Methods` mixin that `Client` supplies
  `call` for. There is no third generated file.
- `x-porcelain.doc` is corrected to `docs/PORCELAIN.md` in the same
  contract edit; the generator ignores that field, so the drift gate is
  unaffected.

### `crates/client/src` (~180 lines, hand-written)

`lib.rs` — `Client { reader: BufReader<UnixStream>, writer: UnixStream,
next: RequestId, daemon_wire: String, poisoned: bool }`, plus `connect`,
`call<M: Method>`, `call_raw`, `set_read_timeout`, `daemon_wire`.
`protocol.rs` — `decode_line(&[u8]) -> Result<Response, Protocol>`, the
fuzzed function. `error.rs` — the enum from answer 5.

HAR posture, all of it enforced rather than asserted: `forbid(unsafe_code)`
through the workspace lints; no `unwrap`/`expect`/`panic` (clippy denies
them outside tests); `RequestId(u64)` a newtype and its increment
`checked_add`; `#[non_exhaustive]` on the public error enums so a later
variant is not a break; error variants carrying the offending value
(`Decode` carries the method and both versions, never a rendered string);
no `_ =>` arm on an enum this crate owns; parameters taking `&str` and
`&[T]`; `#[must_use]` where a result is the whole point; every Rust item
named in a doc comment written as an intra-doc link, which
`rustdoc::broken_intra_doc_links` makes a build failure.

### `clients/python/grid_client` (~150 lines, hand-written)

`__init__.py` re-exporting by name (never `import *`), `client.py` with
`connect`, `call`, `close`, the context manager and `_decode_line`, and
`pyproject.toml` declaring `dependencies = []`. Tests under
`clients/python/tests/`, the binary located by `GRID_BIN`, else
`target/debug/grid`, else `grid` on `PATH`.

## Steps

the commit body, and carries its own doc changes rather than deferring them
to a sweep.

`grid serve`, the never-sent error `data`, and the missing daemon-side

## Verification

1. `just check`, judged by `$?` and never by piped output. Then `just lane
   test`, which carries the invariant that the gate regenerated nothing —
   load-bearing here, since both the wire crate and the Python client are
   generated.
2. `just wire` on an unchanged contract produces an empty diff; rename
   `grid.version` in a scratch copy and `check_wire_drift.py --selfcheck`
   names `methods.rs` **and** `methods.py`.
3. The real binary against a real tree, this repo being the corpus grid
   always has: `cargo build -p grid`, `./target/debug/grid serve` in one
   shell; in another `cargo test -p grid --test client` and
   `GRID_BIN=target/debug/grid python3 -m unittest discover -s
   clients/python/tests -t clients/python`; then by hand, `grid resolve
   Segment::parse --json` against the same call through the Python client.
   The two JSON documents must be equal.
4. `cargo +nightly fuzz run client_response -- -max_total_time=60` before
   step 2 is claimed; only the minimized artifacts are committed, so
   `check_blob_size.py` has nothing to say about the corpus.
5. `mypy --strict clients/python` and `codespell` clean.

## Not built, recorded as decisions

A daemon-spawning constructor (`grid serve` unlinks its socket path, so
spawning against a live one steals it; lifecycle is the caller's); a
`pipeline` API (a local socket against a serial daemon; the id-matching
property that would make it safe is built and tested anyway); a
client-side cache (the key is stated in answer 7 and belongs to the
caller); reconnect or retry (three methods write); a `resume` helper for
aground walks (the contract's rule is "issue a new walk"); a generated
`errors.rs` (a test over `components.errors` catches the same drift for a
fraction of the machinery); a Python byte-mutation fuzzer (corpus replay
across the two decoders is the honest version); a Python file-size ratchet
(it would fire only on generated output); async clients (`tokio` is banned
and the daemon is serial); the daemon-side major refusal (a TODO row: it
needs an additive `grid.version` param and is the daemon's change, not the
SDK's); the TypeScript client, the MCP toolkit and the embeddable engine
crate (scope, above).

`--selfcheck` decides which files must drift by reading the committed outputs
for the method name it renames, rather than by a hardcoded file list, so

**Step 2**, 2026-09-02, five deviations from the text above:

- Answer 2 lists the client's dependencies as "`grid-wire`, `serde`,
  `serde_json`". `serde` is not among them: nothing in the crate names it —
  the `Serialize` and `DeserializeOwned` bounds arrive through
  `grid_wire::methods::Method`, and `serde_json::to_value`/`from_value` carry
  their own — so declaring it fails `cargo machete`. The lockfile gains the
  workspace member and no package.
- Answer 5's `UnexpectedId` is split into `NullId` and `ForeignId`, with
  `MissingId` added beside them. A null id is the daemon saying it could not
  parse the line this client wrote; a foreign id is a desync; an absent `id`
  key is neither. The caller's reaction differs in each case, and one variant
  could not say which had happened.
- `call_raw` takes `&Value`, not `Value`: `json!` serializes through a
  reference, so the by-value form is `clippy::pedantic`'s
  `needless_pass_by_value`, and the fix is the signature rather than an allow.
- The Design section says the client is `!Sync`. It is not marked so: `&mut
  self` on every call is what makes one connection one user, and a marker
  would only forbid sharing `daemon_wire` and `set_read_timeout` across
  threads, which is harmless.
- `gone()` maps `BrokenPipe` and `ConnectionReset` on the write to
  `Disconnected` alongside EOF on the read. A daemon that exited between two
  calls presents as any of the three depending on who wins the race, and they
  are one fact to a caller.

- The step list names "the README crate-table row". Step 2 landed it already,

- The five verbs are five assertions in one test rather than five tests. They

Perf row, measured on this machine (debug build, macOS, unix socket, 2000
calls after 100 warm-up, two runs): one `grid.version` round trip through
`grid_client::Client` costs **35.2 µs** and **31.0 µs**; the same call made
raw by the conformance harness — which opens a fresh connection per call, as
that harness does — costs **49.8 µs** and **50.0 µs**; the same raw bytes on
a connection held open cost **37.1 µs** and **38.6 µs**. The client is not
measurably slower than hand-rolled framing on the same connection; the
harness's extra ~12 µs is its `connect(2)` per call, which the client does
once. Nothing is rounded into holding: the numbers are a debug build's, and
the daemon serves connections serially, so a held-open client blocks every
other connection for as long as it lives — which is why the perf measurement
had to drop its client before timing the raw loop.

**Step 4**, 2026-09-03, six deviations from the text above:

- The Design section says schema descriptions "become docstrings". They become
  `#` comments. Seven schemas have a field named `from` or `def` — Python
  keywords — so every `TypedDict` is emitted in the functional form
  `TypedDict("X", {"from": ...})`, which is the only form that can spell them,
  and that form has no docstring slot. One shape for all 93 objects beats a
  docstring for the 86 that could have had one.
- Every reference from one generated Python name to another is a string forward
  reference, and both files carry `from __future__ import annotations`. Nineteen
  schemas reference one defined later in the contract, and contract order is the
  order both `lib.rs` and `schemas.py` are emitted in, so the two files diff side
  by side. A topological sort was the alternative and is not possible in general
  — a recursive schema has no order — so it would have needed string references
  anyway, for a file that no longer matches its Rust twin.
- Answer 1 says `check_wire_drift.py` copies each generated directory into the
  scratch tree. It also had to stop comparing `__pycache__`: `copytree` already
  ignored it on the scratch side, which made every committed `.pyc` a
  one-sided difference and therefore drift. The comparison now skips that
  directory on both sides.
- Answer 4's socket-path resolution ("explicit argument > `GRID_SOCKET` >
  `<root>/.grid/grid.sock`") is not implemented in the Python client, because it
  was not implemented in the Rust one either: `Client::connect` takes a path and
  defaults nothing, since the daemon resolves its own default against *its*
  working directory, which neither client can know. Two clients with one rule
  beats two clients with two.
- The plan's fault table is one test per row against a fake daemon. The rows that
  are purely about reading a line — truncated, not UTF-8, not JSON, not an
  object, a bad `jsonrpc`, a missing `id`, both bodies, neither, a malformed
  `error` — call `_decode_line` directly instead, because a fake daemon adds a
  thread and a socket to a function that takes bytes. The rows that are about a
  *connection* — a null id, a foreign id, EOF, poisoning, and the three handshake
  rows — go through the fake, which is what they need.
- `_decode_line` catches `RecursionError` beside `ValueError` around
  `json.loads`. Python reports a nesting overflow that way, and the corpus-replay
  claim is that nothing but a `GridProtocolError` escapes; `serde_json` returns
  its depth limit as an ordinary `Err`, so this is the Python spelling of the
  same refusal rather than a new one.

`.mypy_cache/` joins `.gitignore` beside `__pycache__/`: the guardrails' new
optional tool writes it, and it is a build artifact like `target/`.

**Review pass**, 2026-09-03. Twelve findings from the review of steps 1–4 were
each reproduced by a second reader before being fixed; what the fixes changed
against the text above:

- **The handshake no longer decodes typed.** Answer 6 says "Client 1.1 against
  daemon 1.2: connect succeeds", and it did not: `connect` asked `grid.version`
  through `Client::call`, so `VersionResult`'s `deny_unknown_fields` refused a
  same-major daemon whose version result had grown a key — and `connect` is the
  one call a caller cannot route around through `call_raw`, which the same
  answer names as the forward-compatible path. It now reads `wire` off the
  untyped answer. The `Error::Decode` that answer 6 predicted at the handshake
  cannot arise there any more, and the empty `daemon_wire` it used to print is
  gone with it. `Protocol::BadWireVersion` widened to cover an absent or
  non-string `wire`, which was previously a `Decode` in Rust and a bare
  `KeyError` in Python.
- **Both decoders refuse an error code too wide for an `i32`, and Python
  refuses a lone surrogate escape.** Answer 4's fault table is one table for two
  clients; these two inputs were the two places they disagreed, and a
  disagreement here is the one thing the shared table exists to prevent — Rust
  poisoned the connection where Python returned the daemon's own error class,
  and Python decoded a string that raises on any later encode. Both rows are now
  in both fault tables. The surrogate check re-encodes only when a cheap scan
  finds an escape in the surrogate block, so it is not a walk of every response.
- **Both clients bound the response read.** har-threat's rule — "bound every
  read; `Read::take` on the stream, not a check after the buffer is already
  full" — fires by its own trigger on a decoder over bytes it did not write, and
  neither client had a ceiling. `MAX_LINE` is 256 MiB on both sides, an
  availability bound rather than a framing limit the contract declares, and a
  line that reaches it arrives at the decoder without its newline and is refused
  as truncated. It has no test: exercising the cap costs 256 MiB of socket
  traffic per run, and the behaviour it produces — an unterminated line is never
  parsed — is the row already defended. `Protocol::Truncated`'s message no longer
  says the socket closed, because now it may not have.
- **Two green tests were green for the wrong reason.** The Python truncation row
  passed with its guard deleted, because the decoder drops a trailing byte to
  strip the frame and the mangled body then failed as not-JSON; it now names the
  fault rather than merely raising, which is the only way Python can assert what
  Rust asserts with an exact variant. The Python "extra keys survive" handshake
  row asserted only `daemon_wire`; it now scripts a second reply carrying a key
  no generated shape declares and asserts it comes back, as its Rust twin does.
- **`test_differential.py` reaps its daemon through `addClassCleanup`.**
  `unittest` runs `tearDownClass` only when `setUpClass` finished, so any raise
  after the daemon started — a version mismatch, a survey the daemon refuses —
  left `grid serve` alive holding the runner's inherited stdout. Measured before
  the fix: the run reported `FAILED (errors=1)` and the shell did not return for
  two minutes; after, it returns in 0.14s with no surviving process.
- **The manifest check's "stdlib only" law had four bypasses**, one of which
  arrives by itself: `dependency-groups` (PEP 735), `build-system.requires`
  beyond the declared backend, `pdm.lock`, and a virtualenv, which self-ignores
  and is therefore invisible to `git status`, `check_blob_size.py` and the "the
  gate wrote nothing" invariant alike. A fifth, an `.egg-info` beside the
  package, is what an editable install into the ambient environment leaves and
  is how this pass first produced the artifact. Answer 9 enumerated five
  lockfiles; the enumeration was the defect, because C54 claims the law is
  *mechanical* rather than reviewed. All five now fail the check.
- **The hygiene check's Python glob is scoped to grid's own code**,
  `clients/*/grid_client` and `clients/*/tests`, the way its Rust half is scoped
  to `crates/*/src`. Unscoped, a local virtualenv put third-party code inside
  the gate: a `from .x import *` in django failed the build for code nobody here
  wrote, and `mypy --strict`, running in the same script, skipped those same
  files — one gate, two disagreements about what grid's code is.
- **C54's replay clause is narrowed to what runs.** `test_corpus.py` skips on
  every clean checkout and in every CI run, because no job runs a fuzzer and the
  wave's own 60-second run committed nothing. The clause now says "on the day
  that rung produces an input", with the reasoning in ASSURANCE's own "What CI
  does and does not run" section, following C3's precedent, and the missing job
  filed as T-63. A hand-written seed corpus was rejected: it duplicates the
  fault table and makes the test's own claim — that these are the inputs the
  rung found — untrue. The one line the replay was the sole defender of, the
  `RecursionError` catch, is now a row of the fault table instead.
- **`x-porcelain.version` is tied to the build.** It was the fourth spelling of
  the porcelain version and the only one no code read and no test reached, so it
  could drift in silence; `conformance.rs` now compares it against the answer
  the daemon serves. Pre-existing, and outside the SDK's own diff.
- **Answer 8's "doc tests on every public item" is not what landed**, and this

  walk and `Client::connect` — the two entry points a consumer starts from. The

  differential against the CLI, a fuzz target), so eleven more `no_run` examples
