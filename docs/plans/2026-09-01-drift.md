# Drift: interface identity, dependent staleness, and stale tests

Status: proposed; revised 2026-09-01 after the deep-read of the four
research references (`docs/research/ANALYSIS.md`) — added snapshot-
membership segments (step 6, from HyperDiff) and the watch mode (step 9,
from DBSP). Scope: the drift family from the 2026-09-01 ideation
review — a `sig` interface identity beside the datum, a `grid drift` verb
that names dependents of changed interfaces, observed-edge decay, declared
covenants, stale-test surfacing, and the live watcher. Ordered by
dependency and cost. Authority: ONTOLOGY.md for vocabulary, ASSURANCE.md
for dependency discipline, PORCELAIN.md for output shape, LANG_RS.md for
the Rust frontend's ceilings, docs/research/ANALYSIS.md for the paper
verdicts steps 6 and 9 rest on.

Positioning, so the scope stays honest: the compiler already catches a
proven-typed Rust caller of a changed signature. Drift's value is exactly
where the compiler is blind — cross-language edges, re-export hops,
Python callers of anything, runtime-only coupling (wake), and declared
coupling through a serialization boundary (covenants). Prior art
(cargo-semver-checks, buf breaking, test-impact analysis) each hold one
piece; none joins caller graph + content identity + runtime traces +
verdict cache. That join is the feature.

Standing rules for every step (the repo's own, restated):

- **Additive wire evolution only.** New fields are `Option` +
  `skip_serializing_if`; new records are new structs; nothing is
  repurposed. The segment format is the versioned binary: the one epoch
  bump in this plan is declared in step 1, and `Segment::parse` keeps
  reading every epoch ever shipped, pinned by committed fixture.
- **No new dependencies.** Everything here is walks over data grid
  already owns plus `blake3` hashing it already does.
- **Perf budget holds.** `grid survey` on this repo stays under 50ms
  release (sig hashing adds one blake3 per def — re-measure and say the
  number in the PR). `grid drift` on this repo (~1.1k defs, ~2k edges)
  stays under 10ms on a warm store.
- **Panic budget zero, HAR posture.** New index math `get`-guarded or
  saturating; no `unwrap` outside tests; closure walks copy the cache
  crate's budget discipline — **rejected, never truncated** (a truncated
  walk is indistinguishable from a smaller one).
- **Every step lands with its conservatism test** — the assertion that
  the feature *declines* what it cannot prove, and that the declination
  is counted and visible, never silent.
- **Evidence grades are load-bearing.** Proven and observed edges may
  gate (exit 3). Modeled may gate only when a human declared it
  (covenant). Heuristic never gates — it ranks, like hotspots.

Sequencing (each step independently shippable, gates green between):

```
1. sig identity          (epoch 3 — the load-bearing base)
2. grid drift, proven    (the verb; needs 1)
3. observed decay        (small; wake bookkeeping, needs nothing)
4. covenants + observed drift  (needs 2, 3)
5. drift --tests: verdict-stale (needs wake test registry, not 1)
6. membership segments   (history as merge-joins; needs nothing above)
7. green-but-stale       (needs 5, 6, and the patch log)
8. certified aground     (small; leadline contract, needs nothing)
9. watch mode            (signed-delta suspect maintenance; needs 1, 2)
10. co-change ranking    (deferred; cut line below)
```

## 1. `sig`: the interface identity

**Problem.** The datum hashes the whole normalized AST, so a body-only
edit is indistinguishable from a signature change. A drift verb keyed on
the datum would implicate every dependent of every edit — noise kills it.
Drift needs to know *which* changes a dependent can even see.

**Design.** Each `Definition` gains a third identity beside `datum` and
`shape`:

```rust
// grid-datum: Definition gains
/// `blake3` of the frontend-canonical interface bytes — everything a
/// caller can depend on without reading the body. Same constructor
/// discipline as the datum: only a frontend's normalizer builds one.
pub sig: Datum,
```

No new constructor: `Datum::of_canonical_bytes` over frontend-canonical
sig bytes. Each frontend owns its canonical form, with one rule deciding
inclusion: **a fact is in the sig iff a caller can observe it without the
body**.

Rust (`lang-rs`):
- `fn`: visibility, `const`/`async`/`unsafe`/`extern`, name, generic
  params + bounds + where clauses, parameter *types* (patterns erased to
  `_` — Rust callers cannot name parameters), return type, all as
  normalized-written.
- `struct`/`enum`: visibility, name, generics, field names + types in
  declared order, variant list, and attributes that change the observable
  contract: `#[repr(..)]`, `#[serde(..)]`, `#[non_exhaustive]`. Other
  attributes and doc comments are body-side.
- `trait`: name, generics, supertraits, each method's sig (recursively),
  associated types/consts.

Python (`lang-py`):
- `def`: name, decorator list (a decorator rewrites the callable a caller
  gets), parameter names (keyword callers depend on them), annotations,
  `*`/`**` markers, and default-value presence **and value** — a changed
  default silently changes every caller that omits the argument, which is
  precisely hidden drift.
- `class`: name, base list, class-level annotated assignments, `__init__`
  sig.

**Segment: epoch 2 → 3.** New section `SigHash`, 32 bytes per def,
mirroring the datum section. Before flipping `FORMAT_EPOCH`, commit an
epoch-2 fixture image beside the epoch-1 one; epoch-1 and epoch-2 images
parse forever and answer sig queries with *unknown* (`None`), never a
fabricated hash.

**Wire (additive).** `DefChange` gains:

```rust
/// Whether the interface identity changed, when both snapshots carry
/// sigs. `None` means at least one side predates epoch 3 — consumers
/// treat unknown as changed (conservative).
#[serde(skip_serializing_if = "Option::is_none")]
pub sig_changed: Option<bool>,
```

`grid diff` porcelain: a `def ~` record whose sig also changed gets its
hash transition annotated `sig` in the trailing column, so a human can
see body-only vs interface edits at a glance. Column additions are
additive per PORCELAIN.md versioning.

**Tests.**
- Ground truth: fixture pairs per language — body-only edit (datum moves,
  sig holds), param type change (both move), rename (shape holds, sig
  moves), serde attr change on a struct (sig moves), doc comment edit
  (nothing moves).
- Property: sig is invariant under formatting/comments (same corpus the
  datum invariance tests use); `sig_changed == Some(false)` whenever the
  datum is unchanged.
- Conservatism: diff against an epoch-2 image yields
  `sig_changed: None`, and step 2's drift treats it as changed.
- Epoch: both old-epoch fixtures still parse; sections beyond their
  declared count answer unknown.

## 2. `grid drift` — dependents of changed interfaces

**Problem.** After an interface change, the set "dependents that did not
change" is exactly what the compiler cannot enumerate across languages,
re-exports, and processes — and what an agent needs before claiming done.

**Design.** New verb, new rpc, pure computation over two snapshots:

```
grid drift [base] [head] [--floor <zoc>] [--track <file>] [--json]
```

Defaults: `base` = the same base the bare `grid` verb diffs against,
`head` = a fresh worktree survey (idempotent, ~40ms). `--floor` defaults
to `proven` in this step (steps 3–4 widen it to `observed`).

Definition of a **drift suspect**, precisely:

- Changed set `C` = defs in `MadeGood(base, head)` with action `Removed`,
  or `Modified` where `sig_changed` is `Some(true)` **or `None`**
  (unknown is treated as changed — conservative, per step 1).
- For each `d ∈ C`, walk inbound edges *at base* (dependents were
  depending on the old interface) with relation in `{Calls, Constructs,
  Implements, WritesField}` and `zoc` at or above the floor.
- Dependent `c` is a suspect iff `c`'s datum is unchanged from base to
  head and `c ∉ C`. (A dependent that changed at all is assumed handled;
  the gate, not drift, judges whether it changed *correctly*.)

**Track suppression.** With `--track`, a suspect `c` whose callsign
matches a `TrackDefPromise` with action `Modify` or `Remove` is
suppressed: the promise says `c` will be updated, and `grid gate` already
holds when a promise is not made good. Drift lists what nobody has even
promised to touch; the gate judges promises. No new gate concept — drift
composes with the existing xte machinery through the same `Track` and
`MadeGood` shapes, and `DeltaProvider` implementations need no change
beyond `sig_changed` flowing through.

**Refusals are part of the answer.** Drift claiming "no suspects" where
it cannot see callers is dishonest silence. The report carries the
unchecked counts, and porcelain prints them:

```rust
// grid-wire (new structs, additive)
pub struct DriftSuspect {
    pub dependent: DefRef,          // callsign, datum, file:line
    pub changed: DefRef,
    pub relation: Relation,
    pub zoc: Zoc,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub reason: Option<String>,     // step 3: "stale-trace"; step 4: covenant via
}
pub struct DriftUnchecked {
    pub unresolved_refs: u32,       // survey's declined count at head
    pub budget_rejected: u32,       // closure walks refused, not truncated
}
pub struct DriftReport {
    pub base: SnapshotId,
    pub head: SnapshotId,
    pub suspects: Vec<DriftSuspect>,
    pub unchecked: DriftUnchecked,
}
```

**Porcelain.** New record tag (PORCELAIN.md table addition):

| tag | columns |
| --- | --- |
| `drift` | evidence grade, dependent callsign, `<-relation-`, changed callsign, sig transition (`old8→new8`), dependent `file:line` |

`miss` records (existing tag) close the output when `unchecked` is
nonzero: `miss <n> unresolved references unchecked`. Hints to stderr as
usual.

**Exit codes** (uniform): 0 no suspects, 3 suspects exist, 2 bad input
(unknown snapshot, unparseable track), 4 stale coordinate. `--json`
emits `DriftReport` verbatim.

**Tests.**
- Ground truth: a two-language fixture — Rust struct's serde field
  renamed; the Python caller that builds the dict for it is a suspect;
  the Rust caller that also changed is not.
- Properties: `drift(S, S)` is empty; drift is deterministic for a
  snapshot pair (byte-identical output, any machine); suppressing with a
  track never *adds* a suspect.
- Differential (har-verify rung 5): drift computed from segments equals
  drift recomputed from the wire `MadeGood` by an independent
  reimplementation in the test.
- Conservatism: a dependent reached only through a glob import is not a
  suspect and is counted in `unchecked.unresolved_refs`; a closure walk
  over budget rejects the whole answer for that def (exit 1 with a
  named reason), never a partial list.

## 3. Observed-edge decay

**Problem.** A wake edge observed at snapshot S asserts coupling *as the
code was at S*. Either endpoint edited since, and the edge is a claim
about code that no longer exists. Left unhandled, drift over wake edges
rots into false positives within weeks.

**Design.** Wake ingestion already resolves hops against the chart
([wake/src/lib.rs:107](../../crates/wake/src/lib.rs)). Persist, per
observed edge, the endpoint datums at ingestion time (wire: two new
`Option<Datum>` fields on the stored observation — additive; old wakes
load with `None`).

Decay rule, applied wherever an observed edge is *used* (drift, leadline,
suspects — one shared function in `grid-wake`):

- Both endpoint datums unchanged since ingestion → grade stays
  `Observed`.
- Either endpoint's datum changed, or ingestion datums are unknown (old
  wake) → grade demoted to `Heuristic`, reason `stale-trace`.

Demoted edges fall below drift's default floor and appear only under
`--floor heuristic`, with `reason: stale-trace` in the record. The
demotion is display-and-query-time — the stored wake is never rewritten
(append-only story preserved).

**Tests.** Ground truth: ingest a wake, edit the callee body, drift
shows the edge only at `--floor heuristic` with `stale-trace`; re-ingest
a fresh wake and it returns to `observed`. Conservatism: an old-format
wake (no datums) is demoted, not trusted.

## 4. Covenants and observed drift

**Problem.** The serde boundary, the JSON contract, the Python dict a
Rust struct deserializes — coupling the language's binding rules can
never fix. A human knows the pair. Grid has nowhere to write it down.

**Design.** A covenant is a declared, symmetric coupling between two
callsign patterns:

```rust
// grid-wire (new, additive)
pub struct Covenant {
    pub a: CallsignPattern,
    pub b: CallsignPattern,
    pub via: String,                 // "schema", "wire", "protocol" — free text
    #[serde(skip_serializing_if = "Option::is_none")]
    pub note: Option<String>,
}
```

Storage follows the standing-invariants precedent exactly
([standing.rs](../../crates/grid/src/standing.rs)): `.grid/covenants.json`,
a JSON array, absent = empty, unreadable = loud error at the caller,
never a silent pass.

> Open question, flagged not solved here: README says gitignore `.grid/`
> wholesale, but invariants and covenants are declarations, not caches —
> they should travel with the repo. Recommendation: document the split
> (`.grid/` ignored except `invariants.json` and `covenants.json`) in
> README when this step lands. Cheap, no format change.

CLI:

```
grid bind <A> <B> --via <word> [--note <text>]
```

`bind` resolves both patterns against the current snapshot and refuses a
pattern matching nothing — exit 2 with the closest callsigns on stderr,
same contract as `resolve`. `grid bind --list` prints them; removing one
is editing the file (it is a declaration file, like a track).

**Drift over covenants.** A covenant fires on **datum** change, not sig —
the coupling is semantic (a normalizer's *body* is the contract). For
covenant `(a, b)`: if any def matching `a` changed datum while every def
matching `b` held, every held `b` def is a suspect at `Zoc::Modeled`,
`reason: "covenant:<via>"` — and symmetrically. Modeled covenant
suspects **do** gate (exit 3): a human declared the coupling, so the
human meant it. This is the one exception to "modeled never gates", and
it is exception-by-declaration, which is the honesty rule holding, not
breaking.

This step also widens drift's default `--floor` to `observed`, pulling
step 3's decayed wake edges into the default view at their honest grade.

**Tests.** Ground truth: covenant pair, edit one side, drift exits 3
naming the other with `covenant:schema`; edit both, clean. Conservatism:
`bind` refuses an unresolvable pattern; a covenant whose pattern matches
nothing *at drift time* (def deleted) is reported as a `warn` record,
never silently vacuous. Property: covenants are symmetric — swapping `a`
and `b` yields the same suspects.

## 5. `grid drift --tests` — verdict-stale

**Problem.** The cache already knows a test's closure changed — but only
answers when asked about a specific key. Nobody asks. Stale verdicts
need *enumeration*: which known tests need a rerun, pushed, not pulled.

**Design.** The test registry already exists implicitly: every
`grid wake ingest --test <name>` names a test. Drift folds over that
set:

For each test name in retained wakes: recompute the `Kind::Test` closure
key at head ([cache/src/lib.rs](../../crates/cache/src/lib.rs) `Chart::key`).
Three outcomes:

- Key present in cache → fresh, silent.
- Key absent, an older entry exists for this test → **verdict-stale**:
  porcelain `miss <test> closure-changed` (existing `miss` tag).
- Closure walk rejected (budget) → `miss <test> closure-rejected` —
  rejection is a miss, the cache crate's one-directional soundness
  claim, restated in output.

To connect "older entry exists" to a test name, `Entry` gains
`subject: Option<String>` (the test name at `put` time) — additive to
the append-only log line format; old lines load with `None` and such
entries simply cannot be attributed (counted in output as
`miss <n> unattributed entries`, conservatism visible).

Exit 3 when any test is verdict-stale — this is proven-grade staleness
(the closure is identity math), so it gates. `--json` extends
`DriftReport` with `stale_tests: Vec<StaleTest>` (additive field).

**Tests.** Ground truth: record a verdict, edit a def in the closure,
`drift --tests` misses it; edit a def outside the closure, still fresh.
Property: a def edit outside every test closure never stales any test.
Conservatism: budget-rejected closure is stale, never fresh.

## 6. Snapshot-membership segments — history as merge-joins

**Problem.** `grid log`, `bisect`, and every cross-snapshot join in this
plan currently walk the patch chain snapshot by snapshot — the same
per-pair recomputation HyperDiff measured GumTree paying, at the query
layer. Step 7's four-way join over a long chain multiplies that cost by
chain length.

**Design.** The HyperDiff steal (`docs/research/ANALYSIS.md` §2): grid
already has the identity half — the datum *is* the dedup key. What is
missing is the access structure: *identity stored once globally,
snapshots as cheap reference sets into it*, so cross-snapshot questions
become set algebra on stable ids instead of patch replay.

Two new mmap-able segment kinds in the store (additive; not part of the
per-snapshot segment, so no format-epoch interaction):

1. **Membership**: a global sorted table of every datum ever retained,
   plus per retained snapshot a sorted list of datum-id references.
   Any "changed between S1 and S2" is a merge-diff of two sorted
   lists; any "unchanged" check is id-equality — never a load, never a
   diff.
2. **Runs**: per shape-key, `(datum, first_snapshot, last_snapshot)`
   intervals. A definition's bodies over time form contiguous runs, so
   `grid log X` becomes a scan of one shape-key's runs (renames
   included via the shape join) and `bisect` a binary search over run
   boundaries instead of patch replay.

Both are derived data, rebuilt from the retained chain — safe to
delete, like every cache in `.grid/`. Built incrementally: retaining a
new snapshot appends its sorted id list and extends or opens runs;
determinism holds because inputs are already canonically sorted.

Consumers: `grid log` (scan), `grid bisect`/`suspects` (binary search),
step 2's drift (changed set = one merge-diff), step 7's join (below),
step 9's watch state. Beside the datum id, store the small metadata
already computed at hash time (size, complexity) — used to rank
shape-join candidates in rename resolution, HyperDiff's height/size
filtering miniaturized.

**Tests.**
- Ground truth: membership diff of two snapshots equals `MadeGood`'s
  def changes (differential against the existing delta path — the
  har-verify rung-5 harness this repo already favors).
- Property: rebuild-from-chain ≡ incremental append, byte-identical
  (the incremental ≡ full discipline applied to the new segments).
- Conservatism: a snapshot absent from the retained chain is a typed
  refusal (exit 2), never an empty diff.

## 7. Green-but-stale

**Problem.** A test that covered a def, kept passing while the def's
behavior changed, and was itself untouched proved nothing about the
change. Extreme-mutation research (Descartes, pseudo-tested methods)
shows every studied project has these; nobody pays mutation-testing
prices to find them. Grid holds all three facts already and can name
them for free.

**Design.** Rule, over a patch `P` (base → head) in the retained chain:

- def `d`: datum changed across `P` (body moved — sig may or may not),
- test `t`: a retained wake at or before base shows `t` covering `d`,
- `t`'s own datum unchanged across `P`,
- cache holds `Verdict::Pass` for `t` at base's closure key **and** at
  head's closure key (append-only log retains both),

then emit `warn t weak-for d` — `Zoc::Heuristic`, a ranking, **never a
gate** (exit stays 0 for these; the record rides along in
`drift --tests` output and JSON as `weak: Vec<WeakTest>`, additive).

The four-way join runs as streaming merge-joins over step 6's
membership segments: datum changed = merge-diff, test unchanged =
id-equality (never a load — the fast path behind HyperDiff's largest
speedups), coverage from the wake store, the two verdicts from the
cache log. Output streams over the join; per-snapshot def sets are
never materialized (HyperDiff's one un-lazified stage ate 26.6% of its
runtime — the recorded lesson). No new state beyond step 6.

**Tests.** Ground truth: fixture where a covered def's arithmetic flips
and the covering assertion-free test stays green → flagged; a test that
was edited alongside → not flagged; a test that failed at head → not
flagged (it caught something). Conservatism: coverage from a decayed
(stale-trace) wake produces no `weak` record at all — a heuristic built
on a demoted heuristic is noise, and grid declines it, counted as
`miss <n> weak-checks skipped (stale coverage)`.

## 8. Certified aground — a completeness radius on budgeted walks

**Problem.** When a leadline walk runs out of fuel, `Aground` returns the
unexpanded frontier: *where the walk stopped*. It does not say what the
partial answer is good for. A caller holding an aground result cannot
distinguish "every def within 3 hops is in this answer" from "the walk
stopped mid-layer and even depth-1 may be incomplete" — so the honest
uses of a partial result (drift over a bounded blast radius, scope packs
that admit their horizon) are unavailable.

**Design.** Borrowed contract shape, not borrowed algorithm: the
Duan–Mao–Mao–Shu–Yin SSSP result (arXiv:2504.17033) has its BMSSP
subroutine return, on partial execution, a *shrunk boundary* `B′ < B`
with the guarantee that everything within `B′` is complete. The
algorithm itself has no fit here — grid's walks are unweighted BFS,
where a hop is a layer and BFS is already optimal — but the guarantee
shape upgrades `Aground` from "here is where I stopped" to "here is the
radius I *finished*".

Because the walk is strictly layered BFS ([leadline/src/walk.rs]
(../../crates/leadline/src/walk.rs) — a hop budget is only meaningful if
a hop is a layer), the certificate is nearly free: every layer fully
expanded before fuel ran out is complete by construction. The walk
records the deepest fully-expanded layer and reports it:

```rust
// grid-wire: LeadlineResultStats gains (additive)
/// Depth through which the answer is complete: every def reachable
/// within this many hops under the query's filter is in `reached`.
/// `None` on an aground result whose first layer did not finish —
/// the answer certifies nothing, and says so.
#[serde(skip_serializing_if = "Option::is_none")]
pub complete_within: Option<u64>,
```

Semantics, precisely: on `Converged`, `complete_within` equals the
effective hop bound. On `Aground`, it is the last layer the walk fully
expanded before a budget refusal — fuel refused mid-layer means that
layer is *not* certified, and refusal on the first layer yields `None`.
The certificate composes with the filter: complete *under the query's
relations and zoc floor*, nothing broader — one flag, no second walk,
no new fuel accounting.

Scope boundary: this is leadline only. The cache crate's closure
rejection stays a rejection — a closure key is all-or-nothing (a
partial closure would fake a cache hit, soundness claim C4), so a
completeness radius has no meaning there and must not leak in.

Consumers, immediate: `grid scope --depth N` output states its horizon
honestly; step 2's drift, when a track names a bounded blast radius,
can accept a certified-radius answer instead of demanding the full
walk. Porcelain: the `path`/`hop` output's aground banner (stderr)
gains `complete through N hops`.

**Tests.**
- Ground truth: a fixture graph and a fuel budget that exhausts
  mid-layer-3 — `complete_within == Some(2)`, and the depth-≤2 reached
  set equals the unbudgeted walk's depth-≤2 set.
- Property: for every graph, budget, and filter, the certified prefix
  of an aground result equals the same query's converged result
  truncated to that depth (differential against the unbudgeted walk —
  har-verify rung 5).
- Conservatism: fuel refused expanding the roots' own layer →
  `complete_within == None`, never `Some(0)` claimed on a layer that
  did not finish.
- The existing Kani termination harnesses are untouched — the
  certificate reads state the walk already has and spends no fuel.

## 9. Watch mode — signed-delta suspect maintenance

**Problem.** The original ideation ask: a watcher that notices drift as
edits happen, not at CI time. Naive form — rerun `grid drift` per file
event — is correct at this repo's scale but recomputes the world per
keystroke on a monorepo, and its output ("current suspect list") forces
every consumer to diff lists to see what changed.

**Design.** The DBSP steal (`docs/research/ANALYSIS.md` §3) — the
discipline hand-derived, never the framework. Drift-suspects is a
*bilinear* query: one equi-join of inbound edges against the
changed-interface set, plus an antijoin against the changed-dependent
set. DBSP's cost model then dictates exactly what live maintenance must
hold as state, and that nothing else is needed:

- the edge table — grid's resident segment already is the integral of
  all edge deltas;
- the changed-sig set since the session's base snapshot — small,
  in-memory.

Per file event in `grid serve` watch mode: re-survey the file (the
per-file cache makes this the changed file only), diff sigs → Δchanged,
then the three-term incremental-join form: new edges against known
changes, known edges against new changes, new against new — a
reverse-adjacency probe per changed def, forward probe per changed
edge. Emit **signed deltas**, never lists:

```rust
// grid-wire (new, additive)
pub struct DriftDelta {
    pub suspect: DriftSuspect,
    /// +1 appeared, -1 retracted. A retraction is emitted when an
    /// edit resolves a suspect (dependent updated, covenant satisfied,
    /// interface reverted) — consumers hold a running sum, and the sum
    /// after any prefix of events equals a fresh `grid drift`.
    pub weight: i8,
}
```

Closures are explicitly *not* maintained incrementally — that is the
recursive (nested-stream) case, correct but expensive; the budgeted
invalidate-and-rewalk from `grid cache` stays. ASSURANCE.md gains the
classification table: per-view, linear (sig re-hash — stateless) /
bilinear (suspects — the two integrals above) / recursive (closures —
declared not maintained). Every future watch-mode view declares its row
before it lands.

**Tests** — the four algebra tests, ~200 lines, no deps:
- Differential (exists): incremental after edit ≡ full recompute.
- Sequence-integration: after *every prefix* of a multi-edit sequence,
  the summed deltas equal a fresh `grid drift` — state only corrupts
  across steps, so single-edit tests cannot catch it.
- Retraction: edit-then-revert nets every weight to zero (the group
  inverse law); a suspect resolved by updating the dependent emits
  exactly one `-1`.
- Cold start as one delta: feeding the whole tree as a single event
  equals `grid survey` + `grid drift` — collapses watch mode and the
  incremental ≡ full invariant into one property.

**Conservatism.** A file event the frontend cannot parse emits no
deltas and a counted `miss` (the refusal is part of the stream); an
event burst that outruns the session's budget degrades to a full
re-survey plus list-diff — correct by the cold-start property, slower,
and says so on stderr.

## 10. Co-change ranking — deferred

Patch-log mining ("test T historically edits alongside def D") is the
weakest signal in the family: heuristic-on-heuristic, needs history
depth grid's young repos won't have, and steps 5 and 7 cover the
test-staleness ground with stronger evidence. Cut until 1–9 ship and
demand is demonstrated. YAGNI, recorded here so it is a decision, not an
omission. (When it is revisited, step 6's run segments make the mining
a scan instead of a patch walk.)

Also deliberately out of this plan, recorded in
`docs/research/ANALYSIS.md`: SCC condensation with shared per-SCC
closures (a chart/cache optimization, independent of drift) and the
stack-graph resolution discipline (belongs to the TS frontend plan).
